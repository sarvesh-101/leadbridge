# UPDATE (same day, later) — Upstash Redis quota exhausted → fixed in code

## Incident
Render logs flooded with `ReplyError: ERR max requests limit exceeded. Limit: 500000, Usage: 500005` — the **Upstash free-tier monthly command quota (500K)** was exhausted (~2 weeks early). Every worker/cron was stuck in an AUTH → reject → reconnect loop; cron locks and job recovery were skipped. Not a deploy problem — usage problem.

## Root causes found (quota burn audit)
1. `redis-recovery` cron ran **every 30s** with lock + recovery queries → ~172K commands/month baseline.
2. WS plugin PINGed Redis **every 30s per connection** → ~86K/month.
3. Reconnect storm: on quota errors, ioredis/BullMQ retried per-millisecond (each AUTH = 1+ command, zero backoff) → the flood itself.
4. IMAP pull every 2 min regardless of mail volume.
5. BullMQ stall checks default 10s across 8 workers.

## Fixes (all code, no plan change needed to stop the bleeding)
- **NEW `server/src/utils/redis-health.ts`** — global quota/auth backoff: detects `max requests limit exceeded` + auth errors, disables ALL Redis connections until the top of the next hour, runs a single dedicated PING probe hourly; fires `onRedisRecovered` callbacks on success. Also exports `getSharedRedisOptions()` (exponential reconnect 1s→32s, 10s connect timeout, 5-min keepalive) used everywhere.
- `queues.ts` — `safeAdd()` wrapper: enqueue-time failures now fall back to the DB `PendingJob` table (no job loss); new `reenableQueues()` re-creates queues after recovery without a restart.
- All 7 BullMQ workers — shared connection options + `stalledInterval: 2min` (default was 10s).
- `scheduler.ts` — redis-recovery cron **30s → 5 min**; IMAP pull **2 min → 5 min**.
- `plugins/websocket.ts` — health PING **30s → 5 min**; shared retry strategy.
- `cron-lock.ts` — skips lock entirely while backed off (fail-open, was already fail-open for outages); shared retry strategy.
- `plugins/redis.ts` + `services/websocket.service.ts` — shared options + `noteRedisError()` hooks.
- `cron/redis-recovery.ts` — registers `onRedisRecovered → reenableQueues()` so replay resumes automatically.

## Verification
- `tsc --noEmit` clean; **174 tests passed** (18 files), 8 skipped — no regressions.

## Budget math after fixes
- Recovery cron: ~172K → ~8.6K/month. WS pings: ~86K → ~290/month. Stall checks: ~2.4M-equivalent baseline → ~60K/month. Idle BullMQ worker + lock commands dominate now (~10–30/day idle).
