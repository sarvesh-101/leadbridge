## What was done

### ✅ Step 9 code issue — SMS sends never used the registered sender ID
- Root cause: the Bird (MessageBird) platform API **requires** `from` (the sender the
  recipient sees) on every free-text SMS send, but `sendSms()` only sent
  `to`/`text`/`category` → every SMS was rejected and the dashboard-registered
  `CONVERZ` sender was never used (affects OTPs, payment links, campaigns,
  WhatsApp-fallback alerts).
- Fixed `server/src/services/sms.service.ts`: payload now includes
  `from: config.SMS_SENDER_ID` (default `CONVERZ`). Stale comment corrected.
- Fixed `server/_test-messagebird.ts`: key validation hit the LEGACY API
  (`rest.messagebird.com/balance` + `AccessKey`), which rejects new `bk_…` keys
  → falsely reported a valid key as invalid. Now probes the regional host
  (`us1/eu1/api.bird.com`) with Bearer auth.
- Note: until the CONVERZ sender is DLT-approved in the Bird dashboard, sends
  return a clear 422 instead of failing silently.
