### DB index — invoice idempotency hardened
- **NEW `server/prisma/migrations/20260805000000_invoice_cycle_unique/migration.sql`**
  — partial unique index on `Invoice(clientId, subscriptionId, periodStart)`
  `WHERE status <> 'REFUNDED'` (credit notes legitimately reuse the paid invoice's
  periodStart, so they're excluded). NULL periodStart rows (overage invoices) don't
  collide under Postgres NULL-distinct semantics.
- Applied to local dev DB via `prisma db execute` ✅ (migrations folder is for
  production `migrate deploy` on Railway; local uses db push).
- Webhook `ensureInvoiceForCycle` now recovers gracefully from the race the index
  protects against: `createInvoiceForCycle` catches Prisma `P2002`, re-finds the
  winning row, and reuses it instead of 500ing. Non-P2002 errors rethrow immediately.
