## Section 23 — FIX #9: PER-CYCLE RENEWAL INVOICE GENERATION (month-2+ charges now create invoices)

**Trigger:** User asked to implement the reviewer-flagged follow-up — month-2+ Razorpay charges recorded payment + revenue but never generated a new invoice for the broker.

### The bug
In `subscription.charged` / `invoice.paid`, the handler only marked the latest **SENT** invoice PAID. Month-1's checkout invoice covers that. Month-2+ charges found no SENT invoice → payment + revenue were recorded but **no per-month invoice existed** for the broker.

### The fix (`server/src/routes/webhooks/razorpay.ts`)
- New helper **`ensureInvoiceForCycle(fastify, clientId, subscription, chargeDate, amountInr)`**:
  - Derives the billing cycle from `subscription.startDate` + calendar months elapsed at charge time (`monthsElapsed`, clamped ≥ 0)
  - `cycleStart = startDate + monthsElapsed`, `cycleEnd = +1 month`
  - **Idempotent:** first looks up an existing invoice in the cycle window (`periodStart >= cycleStart && < cycleEnd`) and reuses it — redelivered webhooks or both `charged` + `invoice.paid` firing for the same charge can never duplicate (invoiceNumber is `@unique`)
  - Creates a SENT invoice: description `"{planName} (Monthly) — Renewal cycle N"`, amount = charge amount, issueDate = chargeDate, dueDate/periodEnd = cycleEnd
- Both `subscription.charged` and `invoice.paid` now call it when no SENT invoice exists; `chargeDate` comes from `payment.created_at` (unix s) → `invoice.created_at` → now fallback
- Recorded payment + GST invoice PDF generation preserved on the generated invoice

### E2E test (live, all green ✅)
1. Checkout GROWTH → real Razorpay sub `sub_TLg8aL6GNJFP4k` (month-1 SENT invoice)
2. Month-1 charged → 1 invoice PAID / 1 payment / ₹35,000 ✓ (existing behavior intact)
3. Month-2 charged (+31 days) → **NEW renewal invoice generated** (`Renewal cycle 2`, ₹35,000, period 09-04→10-04), 2 invoices / 2 payments / ₹70,000 ✓
4. Resend month-2 charged → still 2/2/₹70,000 (no duplicates) ✓
5. `invoice.paid` for same charge → still 2/2/₹70,000 (cross-event idempotency) ✓
